# pf conformance fixtures

K277 fixture matrix for `raven-pf`, `pfctl` and `tcpdump`. This tree is test
data and test tooling only; it changes no product code.

```sh
timeout 120 sh tests/pf-conformance/selftest.sh
```

`selftest.sh` runs four independent checks:

1. `check_fixtures.py` validates the manifests, packet/rule schemas, pf.conf
   manifest, `semantics.tsv` donor trace, pcap structure/transport checksums,
   malformed-pcap rejection, and (when `tcpdump` is installed) the committed
   decode/filter expectations.
2. `tests/fixtures/tcpdump/generate.py` regenerates every pcap into a temporary
   directory and the self-test compares the bytes with the committed fixtures.
3. `harness/` is a test-only Rust binary outside the product workspace. It
   drives every `raven-pf` scenario through `raven_pf::Engine` and checks the
   per-packet verdict, state disposition and final counters.
4. `negative_check.sh` mutates a pcap digest and a packet verdict in a
   temporary copy; the checker and harness must reject both. The repository is
   never modified.

A `SKIP` or `KNOWN` is never counted as a pass. Donor-only rows are structurally
validated by `check_fixtures.py`; known product divergences carry the exact
donor reference and the observed verdict in the harness output.

## Packet file format

Fields are whitespace-separated:

```
now direction interface proto source sport destination dport length flags expected disposition [fragment|frag|-] [translation]
```

* `now`: monotonic seconds passed to `Engine::evaluate`.
* `proto`: `tcp`, `udp`, `icmp` or `icmp6`.
* `flags`: `S`/`A`/`F`/`R`, or `-` for non-TCP.
* `disposition`: `-`, `created` or `existing`.
* `expected`: `pass`, `block`, or `queued` for the donor reassembly trace
  (`queued` is rejected for executed `raven-pf` rows).
* field 13: `offset/MoreFragments` (multiple of 8) for the donor reassembly
  rows, `frag` for a boolean IPv4/IPv6 fragment in an executed scenario, or
  `-`.
* field 14 (optional): `src:port>dst:port`, the expected `Decision::translation`
  for a NAT/RDR row; absent or `-` means "no translation asserted".

`# expect-counters ...` lines pin the final `in_pass`, `in_block`, `out_pass`,
`out_block`, `states_created`, `states_expired` and `state_hits` values.

## References

The expected verdicts come from the donor pf/npf state machines, not from an
invented oracle:

* OpenBSD `sys/net/pf.c` (`pf_test`, `pf_match_rule`, `pf_create_state`,
  `pf_purge_expired_states`, `pf_map_addr`), `sys/net/pf_norm.c`
  (`pf_reassemble`, `pf_frag_compare`).
* FreeBSD `sys/netpfil/pf/pf.c`, `pf_norm.c`, `pf_table.c` at
  `133344405f532bd54ff3629a77d4c4e062f01fdb`.
* NetBSD `sys/net/npf/*` and `dist/pf/sbin/pfctl/*` at
  `36eddebcc36cb0775aa2962005b9c05419a6ff01`.
* Linux `net/netfilter/nf_conntrack_core.c`, `nf_nat_core.c`, `nft_nat.c`
  for outcome-only comparison.

No donor code is copied. The pcap fixtures are generated by
`tests/fixtures/tcpdump/generate.py`; their expected decode is captured from
Linux `tcpdump 4.99.1` / `libpcap 1.10.1`.

## Fragment port-rule fix (K380)

The fragment-without-reassembly case follows the donor: `pf_match_rule()` fails
a rule that names a source/destination port when the packet is a fragment
(FreeBSD `sys/netpfil/pf/pf.c:5997-6002`, `PF_VPROTO_FRAGMENT`), so the default
block applies. K380 fixed `Rule::matches` in `raven-pf` to apply exactly that
rule; an address-only rule can still match a fragment. `fragment-no-scrub` is
now an executed scenario (PASS) and the former `KNOWN` entry is gone.
Reassembly (`pf_reassemble`) remains outside the 0.1.0 scope and is `SKIP` with
`D-pf-frag-state`.

`raven-pfctl` (K274) and `raven-tcpdump` (K281) now exist in the product tree,
so the ticket's `cargo nextest run -p raven-pf -p raven-pfctl -p raven-tcpdump`
command runs the real tool suites.
