# pf conformance fixtures

K277 fixture matrix for `raven-pf`, `pfctl` and `tcpdump`. This tree is test
data and test tooling only; it changes no product code.

```sh
timeout 120 sh tests/pf-conformance/selftest.sh
```

`selftest.sh` runs three independent checks:

1. `check_fixtures.py` validates the manifests, packet/rule schemas, pf.conf
   manifest, pcap structure and transport checksums, and (when `tcpdump` is
   installed) the committed decode/filter expectations.
2. `tests/fixtures/tcpdump/generate.py` regenerates every pcap into a temporary
   directory and the self-test compares the bytes with the committed fixtures.
3. `harness/` is a test-only Rust binary outside the product workspace. It
   drives every `raven-pf` scenario through `raven_pf::Engine` and checks the
   per-packet verdict, state disposition and final counters.

A `SKIP` is never counted as a pass. The donor-only rows are structurally
validated by `check_fixtures.py` and carry the exact donor references in their
headers, so K273/K274 can consume them without rewriting the matrix.

## Packet file format

Fields are whitespace-separated:

```
now direction interface proto source sport destination dport length flags expected disposition [fragment]
```

* `now`: monotonic seconds passed to `Engine::evaluate`.
* `flags`: `S`/`A`/`F`/`R`, or `-` for non-TCP.
* `disposition`: `-`, `created` or `existing`.
* `fragment`: only in `fragment.tsv`, `offset/MoreFragments` where offset is a
  multiple of 8.

`# expect-counters ...` lines pin the final `in_pass`, `in_block`, `out_pass`,
`out_block`, `states_created`, `states_expired` and `state_hits` values.

## References

The expected verdicts come from the donor pf/npf state machines, not from an
invented oracle:

* OpenBSD `sys/net/pf.c` (`pf_test`, `pf_match_rule`, `pf_create_state`,
  `pf_purge_expired_states`, `pf_map_addr`), `sys/net/pf_norm.c`
  (`pf_reassemble`, `pf_frag_compare`).
* FreeBSD `sys/netpfil/pf/pf.c`, `pf_norm.c`, `pf_table.c` at
  `133344405f532bd54ff3629a77d4c4e062f01fdb`.
* NetBSD `sys/net/npf/*` and `dist/pf/sbin/pfctl/*` at
  `36eddebcc36cb0775aa2962005b9c05419a6ff01`.
* Linux `net/netfilter/nf_conntrack_core.c`, `nf_nat_core.c`, `nft_nat.c`
  for outcome-only comparison.

No donor code is copied. The pcap fixtures are generated by
`tests/fixtures/tcpdump/generate.py`; their expected decode is captured from
Linux `tcpdump 4.99.1` / `libpcap 1.10.1`.

## Known acceptance blocker

The ticket's second acceptance command names `raven-pfctl` and `raven-tcpdump`.
Neither package exists on `origin/master` `4adc24a2`; they are K274's product
crates. `cargo nextest run -p raven-pf -p raven-pfctl -p raven-tcpdump`
therefore fails before running tests. The fixture self-test and `raven-pf`
parts pass; the tool-package part is reported as a blocker, not simulated.
