# ravenlibc libc gate

Status: the gate definition and the generated status table. The verdict narrative lives only in
`libc/ravenlibc/GATE-REPORT.md`. The gate is evaluated, never asserted: a check is MET only when
its command ran and its evidence file exists.

## 1. Status vocabulary

| Status | Meaning |
|---|---|
| MET | The command ran, the pass rule holds and the evidence file exists. |
| NOT MET | The command ran and the pass rule failed. |
| BLOCKED | A prerequisite (tool, ticket, PG item, input) is absent; the command exited 77 or its input file is missing. |
| INFO | Recorded, never gates. |

A row is MET iff every required check is MET; NOT MET if any required check is NOT MET; otherwise
BLOCKED. The libc gate is MET iff all six rows are MET.

## 3. Thresholds

The thresholds are copied from `16-size-testing-oracles.md` 3.B.9 G1 and live in
`tests/libc/gate/rows.toml`: donor suites 90/90/90/90/85 percent, 250 exclusions, 3600 s soak,
100 built world packages, 197.5 weighted world rows. They are PROPOSED (O-B8) and are not lowered
to make a row pass.

## 4. How to evaluate

```
cargo run -q -p libc-gate -- eval
cargo run -q -p libc-gate -- table
cargo run -q -p libc-gate -- verdict
```

`eval` runs every check, writes `build/libc-gate/<id>.txt` and `.json`, and exits 0 after a
completed evaluation. `verdict` exits 0 only for MET; 1 for NOT MET or BLOCKED.
