# UFS power-cut harness (B64)

The harness has two halves. The host half is implemented and runs now; the
guest half is a documented script because it needs K55 (the UFS disk server)
before a guest can expose its write count.

## Host half

```sh
cargo test -p ufs-powercut-tests
```

`PowerCut` wraps a RAM image and refuses every write after N successful
writes. One deterministic workload (`mkdir`, `create`, `write`, `link`,
`symlink`, `rename`, `unlink`, `rmdir`) runs for every cut in `0..300` on a
fresh copy of `tests/ufs-vectors/golden/ufs2-b4096.img.gz`. Each cut is then:

1. remounted read-only for a tree walk (names, types, regular-file reads);
2. remounted writable for the K52 `verify_allocation` check;
3. optionally run through `fsck_ffs -n` if an oracle binary is configured.

The table is written to `build/ufs-powercut/report.tsv`:

```
cut     findings        repaired        clean
```

`repaired` is `k57-absent`: K57 has not merged a `ReadOnly`/`Repair` mode
yet. `clean` is `yes` only when the read-only walk, the allocation check and
(if present) `fsck_ffs` all succeed. The test prints a summary line such as
`ufs-powercut: cuts=300 clean=217 repaired=0 unrepairable=83 k57=absent`;
OBSERVED 2026-11-11 the 300-cut run takes about 10 seconds.

The image can be overridden with `UFS_ORACLE_IMAGE` (raw) or
`UFS_VECTORS_DIR`. `UFS_FSCK_FFS` or `UFS_ORACLE_DIR` select an oracle
`fsck_ffs`; when absent the table records `k57-absent/oracle-absent`.
K58/WAPBL replay is not implemented because K58 has not merged.

## Guest half (needs K55)

`qemu-cut.sh <image> <cut>` documents the planned QEMU flow: qcow2 overlay,
boot, run the guest workload, kill after the N-th write reported by the host
disk server, convert the overlay back and run `fsck_ffs -n` plus K57. It
currently exits 77 with a `needs K55` message. No fixed absolute paths are
used; the script derives nothing from the caller's home directory.
