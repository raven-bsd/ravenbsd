# 0.1.0 workspace test-build audit (K395)

Status: OBSERVED, 2026-11-21. Base: `origin/master` `879d3d390ba4d344928d0d3183e780645329fb4e`.
Purpose: prove every workspace test target **compiles** on the release candidate commit. This is a
build audit only: no test is executed and no QEMU is started.

## Executive summary

| Result | Count |
|---|---:|
| Workspace packages audited | 480 |
| Test targets compiled | 405 |
| Packages failing to compile | 75 |
| Owned by K394 (`fsd-ufs`) | 1 |
| Proposed K402 (`blockd`/`ramfsd` `root_len`) | 2 |
| Proposed K403 (`pi4-platd` host link) | 1 |
| Proposed K401 (host-build exclusions for target-none fixtures/kernel) | 71 |

The full-workspace command fails fast because Cargo stops at the first failing compile units. A
per-package `cargo test --no-run -p <pkg>` sweep was used to reach all 480 packages; it completed in
**428.48 s** (120 s cap per package, none hit the cap).

The full-workspace log is committed under the evidence directory; the per-package runner is
`tests/release/workspace-build/run.sh`.

## Classification and proposed ownership

| Owner | Scope | Proposed action |
|---|---|---|
| **K394** (existing, Mel) | `fsd-ufs` test initializer `handler_ut.rs:149` missing `root_len` | add the field/constructor; the known release blocker |
| **K402** (proposed, fs/block lane) | `raven-blockd` `handler_ut.rs:22` and `raven-ramfsd` `handler_ut.rs:29` have the same `raven_scheme::Ctx` `root_len` gap | one small fix for the two server tests; same root cause as K394, different crates |
| **K403** (proposed, Pi/platform lane) | `raven-pi4-platd` host test link fails with duplicate `_start` | target-gate or exclude the platform fixture from the host test build; verify it links for its real target |
| **K401** (proposed, build/test lane) | 71 target-none qtest/kernel/fixture packages are compiled for the host by `cargo test --workspace` and fail on E0152/E0432/E0433/invalid-register/link | define an explicit host-test exclusion or target-gated package set; do not weaken their real-target tests |
| **K400** (existing, Kevin) | pre-tag workspace test-build gate (`make check-build`) | consume this audit's exclusion list and fail the checkpoint on an unowned compile failure |

The 71 K401 rows are not product regressions for their real targets. They are `#![no_std]` qtest
fixtures, kernel images or target-specific packages whose host test build is not meaningful:
`raven_rt::spawn` is cfg-gated to `target_os = "none"/"ravenbsd"`, the host `std` panic handler
collides with the fixture's `panic_impl`, and aarch64 asm cannot be assembled by the host compiler.
The build gate must exclude them explicitly (a named list or a workspace/target split), not rely on
Cargo's first-error stop.

## Recommendation for the checkpoint

The **pre-tag checkpoint must run the full test-build audit**, not only `make check-fast`:

```sh
timeout 1800 cargo test --no-run --workspace   # expected to be split/excluded per K401
timeout 900 make check-fast
```

`make check-fast` builds only changed packages and was green while pristine master could not
compile `fsd-ufs` tests. K400 (pre-tag workspace test-build gate) should own the durable gate and
consume the K401 exclusion list; a tag is blocked while K394/K402/K403 are open and while any
unowned compile failure remains.

load 17 during the audit; the 428.48 s runtime is measured and below the 1800 s ticket cap.
