## What 0.1.0 is

RavenBSD 0.1.0 is the first public source + QEMU release candidate: a Rust microkernel and
loader, the service set (init/initfsd/svcd/vfsd/consd/logd/netd/...), ravenlibc, the brush shell,
the base userland and the QEMU `release` profile. x86_64 is the primary QEMU target; aarch64
shares the kernel/userland sources and the Pi 4 release profile.

## Dynamic userland

0.1.0 ships the **dynamic userland build path**: the `release`/`shell`/`pi4-release` profiles set
`[initfs] dynamic = true`; `/bin` programs are dynamic PIEs with
`PT_INTERP=/libexec/ld-elf.so.1` and `DT_NEEDED libc.so.1`, while `/init` and `/sbin` stay
static. The loader and shared libc are staged by `libc-link`. **OBSERVED** in the profiles and
`tests/fixtures/dynamic-userland/check.sh` (the fixture checks PT_INTERP, the interpreter path,
`DT_NEEDED libc.so.1` and the absence of `DF_TEXTREL/DT_TEXTREL`).

The `dynamic-exec` and `dynamic-exec-aarch64` target cases now **PASS** on x86_64/aarch64
(C74ic/C74ie), after the fixture build scripts gained `cargo:rerun-if-changed` for the embedded
PIE; the old stale embed page-faulted at the loader base. C74id also passes `libc-dynamic` and
`libc-threads` (x86_64) plus `libc-dynamic` (aarch64). The packet's
`dynamic-userland-x86_64`/`dynamic-userland-aarch64` rows still have no logs, so the
dynamic-userland packet status remains **UNVERIFIED**.

### aarch64 dynamic proof

The aarch64 dynamic build path exists: `dynamic_supported(aarch64)` in the user build, the
`userland/linker/rust-lld-dynamic.sh` wrapper, and the `patch_aarch64_textrel` post-link step that
removes `DF_TEXTREL`/`DT_TEXTREL` for the non-PIC precompiled core. The
`dynamic-userland/check.sh` aarch64 branch uses the `pi4-release` profile. **OBSERVED** the build
path and the aarch64 dynamic target cases: `dynamic-exec-aarch64` and `libc-dynamic` **PASS**
(C74id). The release packet's `dynamic-userland-aarch64` row itself is still MISSING.

The historical aarch64 file-tools qtest passed at `f8eccc3e` (C74aj report), but that is an older
commit and is not evidence for the current tree. No current Pi 4 board PASS is claimed.

## posix-alarm target evidence (C74hq/C74ig)

`cargo xtask qtest --case posix-alarm` **PASS** on both x86_64 and aarch64 (16/16 markers): the
fixture installs a SIGALRM handler, proves `alarm(1)`, one-shot `ualarm(200000, 0)` and repeating
`ualarm(100000, 100000)` deliver SIGALRM to a bounded `pause()`, and that `alarm(0)` cancels with
the correct remainder. aarch64: alarm ~1009 ms, ualarm ~202 ms, interval ~201 ms, after the
zero-module TCB fix in C74ig (`thread::create` gates on `LIBC.main_tcb()`, not `MOD_COUNT`); the
earlier `ENOSYS` (38) is gone. x86_64: alarm ~1009 ms, ualarm ~202 ms, interval ~202 ms. The
transcripts are `build/qtest/posix-alarm.log`; `build/qtest/posix-alarm.json` records
`"result": "pass"`.
