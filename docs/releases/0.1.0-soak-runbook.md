# 0.1.0 24 h soak runbook

Status: **BLOCKED — no 24 h run exists.** The gate needs a quiet host; the shared
build host has been 6–8× oversubscribed (K149's idle-window matrix is blocked for
the same reason). This runbook makes the eventual run trustworthy; it is **not**
evidence of a pass. Only a completed run may set `result=pass`, and its result
will live in `tests/evidence/soak/<image-sha256>/summary.tsv` (schema:
[`../../tests/evidence/soak/README.md`](../../tests/evidence/soak/README.md)).

The gate itself (owner-only, one uninterrupted run):

```
timeout 90000 make soak-24h
```

which expands to `sh scripts/soak.sh --duration 86400 --interval 30 --profile
release` — a 86400 s workload at a 30 s cycle interval plus a 3600 s margin
(K228 harness, `scripts/soak.sh` + `tests/fixtures/soak/soak_driver.py`).

The TCP soak evidence runner (K300, `scripts/tcp-soak-evidence.sh`) is a
**separate** gate with its own owner command; it does not replace this one and is
not part of this runbook.

## 2. Run identity (record before starting)

```
commit=$(git rev-parse HEAD)
image=build/soak/image.img
image_sha256=$(sha256sum "$image" | awk '{print $1}')
date -u +%Y-%m-%dT%H:%M:%SZ
```

* Profile: `release` (`SOAK_PROFILE` default), release-provenance rule: the image
  must embed the kernel built from the clean checkout at HEAD.
* If `build/soak/image.img` is absent, `scripts/soak.sh` builds it from HEAD at
  the start of the run; record the resulting `image_sha256` immediately — it is
  the `<image-sha256>` directory name in the evidence store.
* Start timestamp (UTC, seconds) and the measured host load go into the first
  `hour-00.log` and the first `summary.tsv` row.

## 3. Hourly checkpoint

While the soak runs in the foreground, a second terminal records one checkpoint
per hour (the exact commands are in
[`../../tests/evidence/soak/runbook-commands.sh`](../../tests/evidence/soak/runbook-commands.sh)):

* UTC timestamp, host load (`/proc/loadavg`), QEMU PID/elapsed/%CPU/RSS, and the
  soak run directory (latest `build/soak/run-*`);
* artifact sizes and growth (`soak.jsonl`, `serial.log`, `serial.stamped.log`);
* service state: QEMU alive, the run directory still growing, `summary.json`
  absent (only written at the end);
* guest serial scan keys (case-insensitive): `panic`, `EXCEPTION`, `fatal`,
  `trap`, `watchdog`, `heartbeat`, `stall`, `QEMU exited`;
* host kernel scan keys: `oom`, `killed process`, `qemu-system`;
* write the hour as `tests/evidence/soak/<image-sha256>/hour-NN.log`
  (`NN` = `00`..`24`) and append the same fields to `summary.tsv`.

A missed checkpoint for more than 15 minutes is an abort criterion (below).

## 4. Stall and panic detection

The harness itself fails on any of: a workload error, a boot timeout, a QEMU
exit, or a missing `cycle-done` heartbeat. The default stall threshold is
`max(30, interval*4)` = **120 s** at the 30 s interval; a stall is a failure,
never a retry, and the driver preserves the run directory.

On a non-zero exit, the evidence is:

* `summary.json` (`result` = `fail`/`stall`/`timeout`/`qemu`, plus `error`),
* `serial.log` / `serial.stamped.log`,
* `soak.jsonl` (per-cycle events; the last `cycle_done` and the failure event),
* any driver failure evidence in the run directory.

## 5. Abort criteria (any one → stop and mark the run partial)

1. The soak process exits non-zero (workload error, stall, boot timeout, QEMU
   exit) — do not restart it to hide the failure.
2. A panic/`EXCEPTION`/fatal line in the serial log.
3. No artifact growth for more than 5 minutes while QEMU is alive (host wedge).
4. Host load sustained above ~4× the CPU count (the measurement is not trustworthy;
   K149's blocked window is the reference).
5. Disk full, OOM kill, or the evidence directory cannot be written.
6. A checkpoint gap over 15 minutes.

Aborting is reported as `result=partial` with the reason in `summary.tsv`; a
partial run is **never** a pass and the gate stays BLOCKED.

## 6. Artifacts

Per-run (from the harness): `build/soak/run-<UTC>/` with `serial.log`,
`serial.stamped.log`, `soak.jsonl`, `summary.json`, `summary.txt`, and the
driver's failure evidence on a non-pass run.

Published evidence (schema in `tests/evidence/soak/README.md`):
`tests/evidence/soak/<image-sha256>/` with `hour-NN.log`, `summary.tsv` and
`SHA256SUMS`. The summary row that closes the run is the only place a `pass` may
appear, and only after 24 h of clean checkpoints.
