# 0.1.0 host check on the merged tree (K416)

Status: OBSERVED, 2026-11-21. Base: `origin/master`
`4feacdb022f5985ee90713d8df349dea62d819ce`. Branch `phil/K416` has no product diff against that
commit.

Purpose: run the complete host suite with `make check` (not `check-fast`) on the merged tree, record
every failure and give it an owner. No QEMU and no qtest was run. No retry was used.

`make check` runs guard, fmt, host clippy, host nextest, doc tests, profiles, provenance, target

The gate fails only on three target-clippy steps. The make wrapper returns 2 for xtask's exit 1.

No host test failed, so there is no test name to own. The 4 skipped tests are pre-existing nextest
skips, not a weakening in this ticket.

## Why `check-fast` is not enough

`make check-fast` passes (exit 0) because `--fast` skips the four target-clippy steps. The full
`make check` fails on three of them. This is the same blind spot K395 recorded for the release
checkpoint: a green fast gate does not prove the target clippy gate.

## Checkpoint recommendation

Before the release tag, require both:

```sh
timeout 3600 make check
timeout 900 make check-fast
```

A tag is blocked while K418 and K419 are open. The host test suite itself is green at this sha, so
the remaining `make check` work is target-clippy debt in two crates.
