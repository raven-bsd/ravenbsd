transcript is still pending and 0.1.0 is not tagged.**

`/bin/brush` is installed but **experimental** in 0.1.0: the login shell is rsh and brush's native
spawn path for std programs is pending **P9a** (the libc spawn backend; P9 landed only the design
and test plan). Do not claim a brush login session. No web browser is installed or claimed for
0.1.0.

## 3. Pi 4 transcript (pending)

No Pi 4 image or board transcript is claimed for this QEMU candidate. REL3 (Pi 4 image/serial) and
REL4 (GENET link/DHCP/ping) remain work in progress, and the board chain also depends on
P8/P8b/P10/P12/REL3c. The required Pi 4 gate is:

* a real serial capture with the kernel banner, login, `raven#`, `ls /bin`, `ping` and clean exit;
* the GENET link/DHCP/ping evidence from `scripts/pi4-net-evidence.sh`;
* the REL3/REL4/P8/P8b/P10/P12/REL3c board results.

`tests/fixtures/pi4-release/gate-markers.txt` and `scripts/pi4-net-evidence.sh` define the required
evidence, but a fixture is not a board result. Every Pi 4 claim remains **UNVERIFIED**.

## 4. Evidence harness

`scripts/release-evidence.sh` records the gate artifacts without inventing evidence:

```
scripts/release-evidence.sh --record-qemu --commit 916c0cad...
    write evidence-qemu.txt with the QEMU image/provenance/transcript hashes
    and qemu_gate=PASS

scripts/release-evidence.sh --pi4-log <board.log> --pi4-net-log <net.log>
    validate the Pi 4 serial and GENET evidence

scripts/release-evidence.sh --check
    validate the gate inputs; exits 1 with the exact `blocked: missing ...` list
```

The current `--check` stops on the missing Pi 4 serial log
(`build/release/0.1.0/pi4-serial.log`). The Pi 4 transcript is the explicit pending input; no
board result is recorded here.

`scripts/release-verify.sh` is the separate REL8 clean-clone verification. Run
`sh scripts/release-verify.sh /tmp/opencode/release-final` on the final release commit; it is not
a Pi 4 board result and does not replace the Pi 4 serial transcript.

## 5. Known limitations

* **Pi 4 transcript pending.** No board serial, login/ping transcript or GENET evidence. Every
  Pi 4 claim is UNVERIFIED. No `0.1.0` tag exists.
* **rsh, not brush.** Brush is installed but experimental; its native spawn backend is pending P9a,
  so the 0.1.0 interactive session is rsh. No browser is shipped.
* **No signed artifact/SBOM.** `make sbom` is described by architecture/10 but has no target; the
  image is not signed.
* **QEMU candidate only.** The x86_64 image is reproducible from the release profile but cannot be
  published as 0.1.0 until the Pi 4 gate and full `make check` pass.

## 6. Default password warning

The release login is **`root` / `raven`**. That is a development default, not a production
credential. Change it before exposing the QEMU instance or a Pi 4 board to any network, and do not
reuse it on a real system. REL1b's release root shadow hash and the 0.1.0 gate remain byte-for-byte
compatible.

## 7. Final gate checklist (owner)

1. Complete REL3/REL4 (and the P8/P8b/P10/P12/REL3c board chain), then capture the Pi 4 serial and
   GENET logs.
2. Run `scripts/release-evidence.sh --pi4-log <board.log> --pi4-net-log <net.log>`; every Pi 4
   marker must pass. No board claim without the log.
3. Run `sh scripts/release-verify.sh /tmp/opencode/release-final` and the full `make check` on the
   final release commit.
4. Re-run `scripts/release.sh --build` on the final release commit to lock the published image
   hash, then review the evidence record.
5. Only then tag the commit and publish the image, SHA-256 values, notes, evidence and provenance.
