# RavenBSD 0.1.0 release notes

Status: **BLOCKED — release candidate only.** The release profile (REL2a/REL2b) and the Pi 4
release image gate (REL3) are not in the tree. The QEMU release-login script and transcript
checker (REL2b) and the Pi 4 GENET evidence helper (REL4/REL4a) are present; no release image,
board log or tag is claimed. The owner creates the 0.1.0 tag only after every gate below and the
full `make check` are green.

K25c is merged on this branch: an image/initfs build now auto-builds the missing
`build/<arch>/uutils` slice. A clean-`uutils` image build succeeds; it is not the release
artifact because the release profile is absent.

`scripts/release.sh --candidate` can build a **development candidate** from the current `base`
profile. The release build is `scripts/release.sh --build`; it refuses to run until the release
profile, the REL2b QEMU gate, the REL3/REL4 Pi 4 gates and a clean tree are present.

## 2. Evidence harness

`scripts/release-evidence.sh` is the gate recorder. It never invents a hash, transcript or tag:

```
scripts/release-evidence.sh --qemu
    run scripts/qemu-release.sh, check build/release/qemu-release.log with
    tests/fixtures/release/check-transcript.sh, copy it to build/release/0.1.0/

scripts/release-evidence.sh --pi4-log <board.log> [--pi4-net-log <net.log>]
    validate the board log with scripts/pi4-release.sh --log and the
    GENET link/DHCP/ping markers with scripts/pi4-net-evidence.sh

scripts/release-evidence.sh --record
    require the release image, QEMU transcript, Pi 4 log and Pi 4 net log, then write
    evidence.txt with commit, image SHA-256, provenance SHA-256 and each transcript/log hash

scripts/release-evidence.sh --check
    validate all gate inputs and recorded files; exit 1 with a `blocked: missing ...` list
```

Current `--check` blockers (exact):

```
release-evidence: blocked: missing profiles/release.toml (REL2a/REL2b)
scripts/pi4-release.sh tests/fixtures/pi4-release/gate-markers.txt docs/pi4-release.md
```

`scripts/release.sh --check` additionally reports `clean-git-tree` until the release commit is
clean.

## 3. QEMU transcript

The release transcript must come from REL2b's `release-login` case via
`scripts/qemu-release.sh` and pass `tests/fixtures/release/check-transcript.sh`. It is not
available yet because the release profile is missing. A pre-release `shell-session` observation on
the earlier base reached the shell but stopped at the first file-redirection check:

```
svcd: all services up
rsh: ready
raven# uname -a
RavenBSD raven 0.1 RavenBSD 0.1 (BASE) #1: 0f171ab3 2026-11-16 x86_64
raven# echo hello > /tmp/a
raven# cat /tmp/a
raven#
```

The case stops at `^hello$`: the shell's `echo hello > /tmp/a` creates no visible content. A second
base (with REL1c login/getty) failed earlier, at `^raven# $` / `^rsh: ready$`, because that case
still expects the pre-login `rsh` prompt. Neither is the release-login transcript.

## 4. Pi 4 transcript

REL3 has not produced a Pi 4 release image; no board log exists. The current Pi 4 material is
host-side/qtest only and remains **UNVERIFIED on hardware**. The GENET evidence helper accepts a
model transcript for its own self-test, but that is not a board result:

```
GENET-NET-LINK speed=1000 duplex=full
GENET-NET-DHCP addr=... gateway=... dns=...
GENET-NET-PING target=... tx=... rx=... rtt_ms=...
GENET-NET-OK
```

The documented EMMC2/root host markers (`docs/pi4-root.md`) are likewise not the release image or
board boot. The Pi 4 release gate is the owner's `scripts/pi4-release.sh --log <log>` plus
`scripts/pi4-net-evidence.sh <log>` output.

## 5. Known limitations

* **Release profile/login missing.** REL2a/REL2b's `profiles/release.toml` and release-login case
  are not in the tree; `profiles/release.d/login.toml` alone is not a profile.
* **Pi 4 release image gate missing.** REL3 has no `profiles/pi4-release*`,
  `scripts/pi4-release.sh`, gate markers or `docs/pi4-release.md`.
* **Shell file redirection.** The current `shell-session`/`base-tools` cases fail at
  `echo hello > file` / `cat file`; the file content is empty.
* **Shell-session prompt mismatch.** On the REL1c base the case expects the pre-login `rsh` prompt
  and exits before it; REL2b's release-login case is the replacement.
* **No signed artifact/SBOM.** `make sbom` is described by architecture/10 but no target exists;
  the image is not signed.
* **No tag.** The 0.1.0 tag is intentionally absent.

## 6. Default password warning

The planned REL2b release login is **`root` / `raven`**. That is a development default, not a
production credential. Change it before exposing the QEMU instance or a Pi 4 board to any network,
and do not reuse it on a real system. The login path is not in the current release profile, so
this warning is prospective. REL1b's release root shadow hash and the 0.1.0 gate stay byte-for-byte
compatible.

## 7. Final gate checklist (owner)

1. Merge REL2a/REL2b (release profile and release-login). Run
   `scripts/release-evidence.sh --qemu`; it must pass `check-transcript.sh` (login, root/`raven`,
   brush, `ls /bin`, `ping 10.0.2.2`, clean init exit).
2. Merge REL3/REL4. Build the Pi 4 release image, capture the board log and the GENET evidence,
   then run `scripts/release-evidence.sh --pi4-log <board.log> --pi4-net-log <net.log>`. No board
   claim without the log.
3. Run the full `make check` on the release commit.
4. Run `scripts/release.sh --build`; verify `SHA256SUMS` and `manifest.txt`, then
   `scripts/release-evidence.sh --record` and review `evidence.txt`.
5. Only then tag the commit and publish the image, image SHA-256, notes, evidence and provenance.
