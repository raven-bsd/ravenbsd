## 3. Evidence harness

`scripts/release-evidence.sh` captures/validates the release gates without inventing evidence:

```
scripts/release-evidence.sh --record-qemu --qemu-log <transcript> --image <image>
    write evidence-qemu.txt with commit, image/provenance/transcript SHA-256,
    qemu_gate=PASS and pi4_gate=UNVERIFIED (no board log)

scripts/release-evidence.sh --record --pi4-log <board.log> --pi4-net-log <net.log>
    full record; requires the release image, QEMU transcript, Pi 4 board log and GENET evidence

scripts/release-evidence.sh --check
    validate all gate inputs; exits 1 with the exact `blocked: missing ...` list
```

## 4. Pi 4 gate

REL3/REL4b/P8 have not produced a Pi 4 release image or board log. The repository has the
`profiles/pi4-release.toml` profile and the GENET net evidence helper, but not
`scripts/pi4-release.sh`, `tests/fixtures/pi4-release/gate-markers.txt` or `docs/pi4-release.md`,

The host-side EMMC2/root markers (`docs/pi4-root.md`) and the GENET model transcript are not a
board release result.

## 5. Known limitations

* **Pi 4 release gate missing.** No board image, serial log, login/ping transcript or REL4b/P8
  evidence. No tag.
* **rsh, not brush.** Brush is installed but its native spawn is pending P9; the 0.1.0 interactive
  session is rsh. No browser is shipped.
* **No signed artifact/SBOM.** `make sbom` is described by architecture/10 but has no target; the
  image is not signed.
* **QEMU release image is a candidate artifact.** It is reproducible from the release profile but
  cannot be published as 0.1.0 until the Pi 4 gate and full `make check` pass.
* **Debug image builds of `sha2` fail** with the LLVM split-result error; use the release user
  build (`RAVEN_USER_RELEASE=1`) for the release image.

## 6. Default password warning

The release login is **`root` / `raven`**. That is a development default, not a production
credential. Change it before exposing the QEMU instance or a Pi 4 board to any network, and do not
reuse it on a real system. REL1b's release root shadow hash and the 0.1.0 gate remain byte-for-byte
compatible.

## 7. Final gate checklist (owner)

1. Merge REL3/REL4b/P8; build the Pi 4 release image and capture the board serial and GENET ping
   logs.
2. Run `scripts/release-evidence.sh --pi4-log <board.log> --pi4-net-log <net.log>`; every Pi 4
   marker must pass. No board claim without the log.
3. Run the full `make check` on the release commit.
4. Re-run `scripts/release.sh --build` on the final release commit to lock the published image
   hash, then `scripts/release-evidence.sh --record`; review `evidence.txt`.
5. Only then tag the commit and publish the image, image SHA-256, notes, evidence and provenance.
