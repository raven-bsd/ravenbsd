# RavenBSD 0.1.0 release notes

Status: **BLOCKED — release candidate only.** The release-profile QEMU login gate (REL2b), the
Pi 4 release image/serial gate (REL3) and the Pi 4 GENET release ping (REL4) are not in the tree
yet. No git tag exists for 0.1.0; the owner creates it only after those gates and the full
`make check` are green.

`scripts/release.sh --candidate` can build a **development candidate** from the current `base`
profile and write a local manifest/hash without claiming it as the release artifact. The release
build is `scripts/release.sh --build`, which refuses to run until the release profile, the REL2b
QEMU gate, the REL3/REL4 Pi 4 gates and a clean tree are present.

## 2. QEMU transcript (current base profile, not the release login)

`cargo xtask qtest --case shell-session --arch x86_64` on `0f171ab3` reached the shell prompt and
printed the version, then stopped at the first file-redirection check:

```
svcd: all services up
rsh: ready
raven# uname -a
RavenBSD raven 0.1 RavenBSD 0.1 (BASE) #1: 0f171ab3 2026-11-16 x86_64
process: child exited (0)
raven# echo hello > /tmp/a
raven# cat /tmp/a
process: child exited (0)
raven#
```

The case stops at `^hello$` (`step 8: no matching serial line within 30 s`): the shell's
`echo hello > /tmp/a` creates no visible content, while `cat` is a uutils child. This is a
pre-release shell/uutils limitation, not a linuxd or image-build failure. REL2b will provide the
real release-profile transcript (login prompt, root/raven, brush, `ls /bin`, `ping 10.0.2.2`).

## 4. Known limitations

* **Release profile/login missing.** REL2a/REL2b are todo; there is no `profiles/release.toml`,
  login userland, default-login qtest or `docs/release-qemu.md` in the tree.
* **Pi 4 release image/GENET ping missing.** REL3/REL4 are todo; there is no
  `profiles/pi4-release*`, `scripts/pi4-release.sh`, `docs/pi4-release.md`,
  `scripts/pi4-net-evidence.sh` or board link/DHCP/ping evidence.
* **Shell file redirection.** The current `shell-session` and `base-tools` cases fail at
  `echo hello > file` / `cat file`; the file content is empty. This blocks a meaningful release
  shell transcript until the shell/uutils path is fixed.
* **No signed artifact/SBOM.** `make sbom` is described by architecture/10 but no target exists;
  the image is not signed.
* **No tag.** The 0.1.0 tag is intentionally absent.

## 5. Default password warning

The planned REL2b release login is **`root` / `raven`**. That is a development default, not a
production credential. Change it before exposing the QEMU instance or a Pi 4 board to any network,
and do not reuse it on a real system. The login path is not present in the current 0.1.0 master, so
this warning is prospective for the release profile.

## 6. Release checklist (owner)

1. Merge REL2b (QEMU release login), REL3 (Pi 4 release image/serial) and REL4 (Pi 4 GENET ping).
2. Fix the shell redirection limitation or record it as an accepted 0.1.0 limitation.
3. Run the full `make check` (not only `check-fast`) on the release commit.
4. Run `scripts/release.sh --build`; verify `SHA256SUMS` and `manifest.txt`.
5. Review this page and the REL2b/REL3/REL4 transcripts.
6. Only then tag the commit and publish the image, hash, notes and provenance.
