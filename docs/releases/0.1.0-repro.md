# 0.1.0 release image reproducibility

Status: **REPRODUCIBLE** for the two release images tested on the host at `origin/master`
`24f8cbff` (2026-11-17). Two builds of each image produced identical sizes and SHA-256 values.
No QEMU run was used; the Pi 4 and x86_64 images were built on the host only.

## Method

`scripts/repro-release.sh` builds each image twice into separate output files (`a.img`, `b.img`)
from the same commit and compares the size and SHA-256. It also copies the constituent build
artifacts (`kernel.elf`, `loader.efi`, `initfs.img`) after each build and compares them, so a
difference is attributed to a named input instead of being reported as a bare hash mismatch.

```
sh scripts/repro-release.sh
sh scripts/repro-release.sh --self-test
```

The self-test exercises only the comparison/diagnosis logic on synthetic files (identical,
same-size different-content, different-size); it does not build an image and cannot produce a
release verdict.

Both builds share the checked-out tree and `target/` (compiler artifacts are reused); the image
assembly — initfs regeneration, FAT, GPT and boot.toml — runs on every invocation, which is where
the image-builder timestamp risks live. A `--clean`/isolated-target mode would additionally cover
compiler determinism; that is not part of this check.

## Determinism verdict and future diagnosis

Both images are byte-identical across two builds. The script's diagnosis, if a future run
differs, names the input by comparing the first differing image byte plus the three artifacts:

* **ELF `kernel.elf`/`loader.efi` differs** — inspect the GNU build-id (`readelf -n`) and the
  `.comment` toolchain string. Fix site: the profile/build flags used by
  `xtask/src/image.rs` and `xtask/src/build.rs`; a `--build-id`/`-C metadata` change belongs to
  the xtask image/profile owner.
* **`initfs.img` differs** — the RAVENFS1 header or per-entry timestamps/modes. Fix site:
  `xtask/src/initfs.rs` (stamp a fixed epoch/commit id instead of the wall clock).
* **All artifacts match but the image differs** — FAT directory timestamps, GPT disk/partition
  GUIDs or the generated `boot.toml`. Fix site: `xtask/src/image.rs` (fixed FAT mtimes and
  deterministic GUIDs; `boot.toml` is generated there).
* **The only difference is a path/toolchain string** — check `CARGO_TARGET_DIR`/checkout-path
  embedding and the pinned `rustc --version`.

No source fix is needed for this record; the exact build inputs above are the ones that
reproduced.
