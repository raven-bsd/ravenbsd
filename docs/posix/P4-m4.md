# POSIX m4 macro processor (P4k)

Status: **DONE for the bounded first-party core.** The `raven-m4` crate implements the
macro-expansion core listed below, and `tests/posix/utility/m4/test.sh` passes 66 host behaviour
cases across nine feature groups. `util.m4` is registered as present only through that script.

## Method

`userland/bin/m4` is a first-party Rust crate (`raven-m4`), `no_std` on the target and
`#![forbid(unsafe_code)]`. It has no kernel dependency and no external dependency; the target
binary uses only `raven-rt` and `raven-tool-core`, while the host binary uses the standard
library for file and standard-input plumbing. The host build is the executable evidence; the
target image does not yet stage `/bin/m4` and no board result is claimed.

```sh
sh tests/posix/utility/run-m4.sh
sh tests/posix/utility/run-m4.sh --list
sh tests/posix/utility/run-m4.sh define quoting
```

The runner builds `build/posix-utility/m4-host` and executes each
`tests/posix/utility/m4/<feature>/test.sh` with `UTIL` set to the host binary. A failing feature
fails the runner; there is no pass without a case.

## Feature matrix

| Area | Implemented | Cases |
|---|---|---|
| Quoting | default `` `'' quotes, nested quote matching, `changequote` (0 or 2 arguments), quoted text is never expanded | 7 |
| Comments | `#` to newline, `changecom` (0, 1 or 2 arguments), copied without expansion, empty start disables | (in quoting) |
| Definitions | `define`, `undefine`, `defn`, `pushdef`, `popdef`, `-D`, `-U`, `$0`-`$9`, `$#`, `$*`, `$@` | 8 |
| Input control | `dnl`, `include`, `-I`, file operands, `-`, standard input | 5 + 14 |
| Conditionals | `ifdef`, `ifelse` including the 3/4/5-argument and chained forms | 8 |
| Arithmetic | `incr`, `decr`, `eval` with C-like precedence, parentheses, comparisons, logical and bitwise operators, `**`, octal/hexadecimal/binary integers | 8 |
| Strings | `substr` (zero-offset), `index` (zero-offset, `-1` when absent), `translit` replacement and deletion | 6 |
| Diversions | `divert`, `undivert` (named, ordered, all), negative discard, EOF flush in numerical order | 5 |
| Diagnostics | explicit `syscmd`/`esyscmd` errors, malformed quote/call, empty definition name, usage errors | 5 |

Expansion order follows the POSIX model: argument text is expanded while it is collected, so a
macro expansion that produces commas or parentheses participates in argument division and
parenthesis matching. The omitted built-ins are `divnum`, `dumpdef`, `errprint`, `len`, `m4exit`,
`m4wrap`, `mkstemp`, `shift`, `sinclude`, `sysval`, `traceon` and `traceoff`; `-s` is not
implemented.

## Known limits and defects

* `syscmd` and `esyscmd` are **explicitly unsupported**: calling either reports
  `<name>: unsupported macro` and exits non-zero. They are not silently ignored.
* `eval` implements one expression argument. The POSIX optional result-radix and minimum-digit
  arguments are not implemented; extra arguments are ignored.
* Diversion numbers above 9 are accepted instead of being implementation-defined.
* The target standard input path opens `tty:console` and reads to EOF. There is no general
  process-stdin handle or pipeline plumbing in the image yet.
* `include` searches `-I` directories first and then the process path; `-I` is the ticket's
  required extension and is not a POSIX option.
* The target image does not yet stage `/bin/m4`; the evidence is the host behaviour suite.

## Evidence overlay

`docs/posix/evidence/P4-m4.toml` contains the `util.m4` row with
`test:tests/posix/utility/m4/test.sh`. The P0b loader accepts the `P4-m4` owner batch file and the
gate executes the script; the row is present only while every case passes.
