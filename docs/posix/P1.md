# P1 batch (a1): missing headers and the libintl interface

Status: P1 first batch, 2026-11-16. This batch adds the headers that were entirely absent from
`libc/ravenlibc/include` and the function interface they unblock. The POSIX gate remains red
overall; the batch rows themselves are green and the overall failure count improves.

## Batch definition

Batch (a1) is the eight missing headers whose declarations do not require a new libc
implementation batch:

`float.h`, `iso646.h`, `libintl.h`, `stdarg.h`, `stdatomic.h`, `stdbool.h`, `stddef.h`,
`tgmath.h`.

Adding `libintl.h` also unblocks the nine `gettext` function interface rows because the C ABI
already exists in `libc/ravenlibc/crates/raven-libc/src/locale/` and the frozen symbol list.

Deferred from this batch:

* `trace.h` (POSIX tracing API needs a dedicated type/function batch),
* `ndbm.h` (database API needs an implementation or an explicit declaration-only decision),
* the 46 `partial` headers whose required declarations are still incomplete,
* the `va_arg`/`va_copy`/`va_end`/`va_start`/`offsetof` rows: these are macros, not exported
  symbols, and the gate's `&macro` interface probe is not a valid test. Closing them needs a gate
  model change or a written waiver, not a libc symbol.

## Headers and standard clauses

| Header | Standard clause | Implementation | Evidence |
|---|---|---|---|
| `float.h` | POSIX.1-2024 `<float.h>`, C17 7.7 | compiler-provided C constants exposed through the libc include root | `tests/libc/posix/headers/check-missing-headers.sh` |
| `iso646.h` | POSIX.1-2024 `<iso646.h>`, C17 7.9 | first-party alternative operator macros | same |
| `libintl.h` | gettext catalog ABI carried by the POSIX profile | first-party declarations; C ABI in `raven-libc-locale` | same |
| `stdarg.h` | POSIX.1-2024 `<stdarg.h>`, C17 7.16 | compiler-provided `va_list`/`va_*` exposed through the libc include root | same |
| `stdatomic.h` | POSIX.1-2024 `<stdatomic.h>`, C17 7.17 | compiler-provided C11 atomics exposed through the libc include root | same |
| `stdbool.h` | POSIX.1-2024 `<stdbool.h>`, C17 7.18 | compiler-provided boolean macros exposed through the libc include root | same |
| `stddef.h` | POSIX.1-2024 `<stddef.h>`, C17 7.19 | compiler-provided `size_t`/`NULL`/`offsetof` exposed through the libc include root | same |
| `tgmath.h` | POSIX.1-2024 `<tgmath.h>`, C17 7.25 | first-party `_Generic` macros over the ravenlibc `<math.h>` real functions; complex generic coverage is a later batch | same |

The compiler-provided wrappers use `#include_next` so the target compiler's own C definitions
remain the single source of truth. They do not copy compiler code into the repository.

## Interface rows closed by `libintl.h`

`bind_textdomain_codeset`, `bindtextdomain`, `dcgettext`, `dcngettext`, `dgettext`,
`dngettext`, `gettext`, `ngettext`, `textdomain`.

These rows were already `present` in the frozen symbol list but failed the gate because the header
did not exist; the new declarations compile against the existing C ABI.

## Evidence overlay

`docs/posix/evidence/P1.toml` carries one `present` row per batch header, with
`evidence = "tests/libc/posix/headers/check-missing-headers.sh"` and the standard clause in the
note. The overlay is applied by the seed and the gate; the generated `docs/posix/profile.toml`,
`traceability.toml` and `GAPS.md` were regenerated with
`cargo run -q -p posix-conform -- seed`.

## Header test

```sh
sh tests/libc/posix/headers/check-missing-headers.sh
```

The script compiles each header with the same POSIX feature macros as the gate
(`-std=c17 -D_POSIX_C_SOURCE=202405L -D_XOPEN_SOURCE=800`) and exercises the macro surface:
`FLT_RADIX`, the `iso646` operator spellings, the nine gettext function names, `va_start`/
`va_arg`/`va_copy`/`va_end`, atomic store/load, `bool`/`true`/`false`, `NULL`/`offsetof`, and the
`tgmath` `sqrt` macro. It is the executable evidence named in `P1.toml`.

## Limits

* The batch proves header presence and declaration compilation, not the runtime behaviour of
  `libintl` catalogs or the generic math macros; behaviour tests remain P1 follow-ups.
* The `#include_next` wrappers assume the pinned host/target compiler provides the C17 headers;
  a compiler without them fails the header test loudly.
* `trace.h` and `ndbm.h` are deliberately deferred; adding `ndbm.h` without its implementation
  would create six new failing `dbm_*` interface rows, so it belongs with the database batch.
* No product ABI, symbol map or `crates/raven-abi` change is part of this batch.
