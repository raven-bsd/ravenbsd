# P5 - filesystem POSIX semantics

This note records the P5 implementation and executable evidence. All 20 filesystem rows were
re-run on `origin/master` `0a3fab65` for the P5h close-out (2026-11-17) and every row passed; the
kernel byte-range record locks are P5c. The machine-readable claims live in
`docs/posix/evidence/P5.toml`; the generated profile, trace and gate report are
`docs/posix/profile.toml`, `docs/posix/traceability.toml` and `docs/posix/CONFORMANCE.md`.

## Implemented surface

The VFS control protocol (`raven-proto-fs`) gained:

* `LINK`, `CHOWN`, `LCHOWN`, `FCHOWN`, `MKFIFO`, `MKNOD`, `UTIMENS`, `STATVFS` and `LSTAT`;
* the fixed `StatVfs` response record and a `Stat` response for `LSTAT`;
* whole-second `UTIME_NOW`/`UTIME_OMIT` selectors and `ID_NO_CHANGE` for ownership.

`ramfsd` and `raven-ramfs-core` now support hard links with real `nlink`, `chown`/`lchown`/
`fchown`, FIFO/device/socket nodes, `utimensat`, and `statvfs`. `fsd-ufs` exposes the same
operations on top of `ufs-core`, whose namespace layer gained a `mknod` creation path.
`vfsd` routes all of them, rejects cross-mount hard links with `EXDEV`, and uses a new `LSTAT`
call for unlink/rename permission checks so a dangling symlink can still be removed.
`raven-vfs-core` gained the `same_mount` helper used by the link path.

P5b adds file-backed mmap: `OP_MMAP` asks vfsd for a pager-backed `MemObject` attached to the
file handle. vfsd serves `PageIn` with `pread` on the backing file and `PageOut` with `pwrite`;
the kernel `MSYNC` 0x44 path flushes dirty shared pages without unmapping. `mmap`/`msync` in
libc use the attached object and the new safe `raven-rt` map/pager wrappers.

## Remaining defects

* **record-lock libc glue**: the kernel implements `RECORD_LOCK` with a `(pid, server, ino)` lock
  table, `F_GETLK`/`F_SETLK`/`F_SETLKW`, blocking wakeup and close/exit release. The libc
  `fcntl` wrapper is still deferred until P1f releases `raven-libc-platform`; the qtest uses the
  raw syscall (`tests/posix/fs/record-lock/test.sh`, case `posix-fs-record-lock`).
* Fault-path exit (a killed process that never reaches the `EXIT`/terminate syscall) does not
  release its locks; the entry stays keyed by the dead pid until reclaimed. That hook would need
  `kernel/src/process`, which this ticket does not own.

The UFS sparse evidence lives in `tests/posix/fs/sparse-file/test.sh` and the `fsd-ufs-rw`
probe. ramfs intentionally stays dense (a `Vec` with zero fill); the row is verified on the
UFS backend. The umask evidence lives in `tests/posix/fs/umask/test.sh` and exercises the
process-local libc mask on `mkdir` and `O_CREAT`.

## Relative symlink readlink

`Readlink` traverses only the parent directories of its operand and never follows the final
component; the final component is resolved with `resolve_nofollow` so the link identity is
preserved. A relative operand (`fastlink`) and an absolute one (`/fastlink`) therefore return
the same target string, and a dangling relative target still reports its stored text. This is
the rule the VFS server now applies; on `0a3fab65` the P5h close-out re-ran
`tests/posix/fs/symlink/test.sh` (3/3 readlink tests), `vfs-aarch64` on x86_64 and aarch64, and
`posix-fs`, all green.

## Scope notes

The directive explicitly added the missing protocol calls to P5. The implementation therefore
touches `crates/raven-proto-fs`, `crates/ufs-core`, `libc/ravenlibc` response matches,
`userland/rt` response matches, the k55 UFS probe and the `fsd-ufs-rw` case, plus the generated
POSIX profile/trace/GAPS/CONFORMANCE files. These are recorded as necessary deviations: the
VFS-level behaviour cannot be claimed without the wire calls and without regenerating the
gate's trace entries.
