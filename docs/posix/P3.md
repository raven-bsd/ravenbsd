# P3 tty, termios and job control

OBSERVED on `stuart/P2m` (base `origin/master` `f44ebb9b`; P3 merged at `6957cb8b`). P3
implements a pty server, session/foreground-group state and a pty job-control QEMU case; P2m adds
the kernel controlling terminal, background-stop and hangup layer. No board claim.

## What is present

* `ptyd` serves `pty:master` and `pty:slave` over one `raven-tty-core` discipline. Master input is
  line-buffered/echoed in canonical mode and passed through in raw mode; slave writes appear on
  the master. Empty non-blocking reads are `EAGAIN`; hangup makes them zero.
* pty CALLs use the `raven-proto-tty` 12-byte shape for `SET_MODE`, `GET_MODE` and `FLUSH`; the
  server-local `SET_FG`, `GET_FG` and `HANGUP` use the same shape. Ctrl-C emits the discipline
  interrupt event and sends SIGINT through `PROC_SIGNAL` to the recorded foreground group.
* `ttyd` serves `ttyd:session` and named `ttyd:session/<id>` sessions, with reference counts,
  session/foreground state, `SESSION_ID`, `SET_SID`/`GET_SID`, a control read/write path and
  hangup state.
* P2m adds the kernel controlling terminal (`TIOCSCTTY`, `tcgetpgrp`, `tcsetpgrp`), the
  background-access policy (`SIGTTIN`/`SIGTTOU`, orphaned `EIO`), and session-leader hangup
  (`SIGHUP` + `SIGCONT`).
* The kernel process model (spawn/setpgid/wait) is used by the job-control fixture to spawn the reader, make it a
  process-group leader and reap its SIGINT exit status; P2m uses the same spawn/setpgid/wait
  path for the `tty-control` child.
* The existing `ravenlibc` termios wrapper over `tty:` CALLs is reused; P3 does not duplicate a
  second termios model.

`docs/posix/evidence/P3.toml` marks canonical, control-character, echo, job-control-glue,
line-discipline, pty and raw as present. P2m makes the controlling-terminal row present in the
documentation while the executable overlay remains outside P2m's Owns; the coordinator refreshes
it at the merge. The remaining explicit waivers are:

* **flow-control**: no IXON/IXOFF or output pause.
* **stty**: no command-line utility yet.
* **termios**: the existing platform wrapper has host tests over mode/echo/flush, but no target
  libc case covers the speed/flag fields; the pty Qtest exercises the protocol only.
* **ttyname**: wrappers exist but there is no target pty identity case.

`process.tty-control` and `process.job-control` are now covered by `qtest:tty-control` and
`qtest:tty-job-control`. The stop/continue model is still a wait status rather than a scheduler
suspension; that P2f follow-up is recorded below.

## Limits

* pty reads are **non-blocking** (`EAGAIN`) because the scheme server is single-threaded; the
  fixture polls. A deferred reader/wakeup worker is a follow-up.
* ptyd has one global master/slave pair, sufficient for the QEMU matrix but not a pty allocator.
* P2f stop signals are wait-status events, not scheduler suspensions; a background process gets
  the stop status and an interrupted syscall, and `SIGCONT` clears the status. True context
  suspension remains a scheduler ticket.
* The `ttyd` session handle has a synthetic read/write path; pty data remains in `ptyd`. There is
  no `TIOCSTI`, `TOSTOP` or background-`tcsetpgrp` signal rule.
* `tcdrain`, `tcflow`, `tcsendbreak` and baud/flow extensions remain ENOSYS/partial.
* No board claim.
