# P3 tty, termios and job control

OBSERVED on `stuart/P3` (base `stuart/P2e` `15d47e18`, merged `origin/master` `14908851`). P3
implements a pty server, session/foreground-group state, a pty job-control QEMU case and the tty
evidence overlay. No board claim.

## What is present

* `ptyd` serves `pty:master` and `pty:slave` over one `raven-tty-core` discipline. Master input is
  line-buffered/echoed in canonical mode and passed through in raw mode; slave writes appear on
  the master. Empty non-blocking reads are `EAGAIN`; hangup makes them zero.
* pty CALLs use the `raven-proto-tty` 12-byte shape for `SET_MODE`, `GET_MODE` and `FLUSH`; the
  server-local `SET_FG`, `GET_FG` and `HANGUP` use the same shape. Ctrl-C emits the discipline
  interrupt event and sends SIGINT through `PROC_SIGNAL` to the recorded foreground group.
* `ttyd` serves `ttyd:session` and records the session id, foreground process group and hangup
  state. It is the state half of the future controlling-terminal glue.
* The P2e `procd` server is used by the job-control fixture to spawn the reader, make it a
  process-group leader and reap its SIGINT exit status.
* The existing `ravenlibc` termios wrapper over `tty:` CALLs is reused; P3 does not duplicate a
  second termios model.

`docs/posix/evidence/P3.toml` marks canonical, control-character, echo, job-control-glue,
line-discipline, pty and raw as present. The explicit waivers are:

* **flow-control**: no IXON/IXOFF or output pause.
* **stty**: no command-line utility yet.
* **termios**: the existing platform wrapper has host tests over mode/echo/flush, but no target
  libc case covers the speed/flag fields; the pty Qtest exercises the protocol only.
* **ttyname**: wrappers exist but there is no target pty identity case.
* **controlling-terminal**: ptyd/ttyd record the logical foreground/session state; the kernel has
  no `TIOCSCTTY`/acquisition operation, so the row is not claimed as complete.
* **process.tty-control** remains a P2 waiver; P3 closes `process.job-control` with
  `qtest:tty-job-control` (foreground handoff + Ctrl-C), while scheduler suspension remains the
  P2f follow-up.

`posix-check` now reports all tty rows as pass/waiver; the overall gate can still be release-blocked
by unrelated utility/interface areas.

## Limits

* pty reads are **non-blocking** (`EAGAIN`) because the scheme server is single-threaded; the
  fixture polls. A deferred reader/wakeup worker is a follow-up.
* ptyd has one global master/slave pair, sufficient for the QEMU matrix but not a pty allocator.
* No kernel controlling-terminal or scheduler stop/resume. P3 records the foreground group and
  sends SIGINT; `SIGTTIN`/`SIGTTOU`, true foreground suspension and `tcsetpgrp` kernel state remain
  follow-ups.
* `tcdrain`, `tcflow`, `tcsendbreak` and baud/flow extensions remain ENOSYS/partial.
* No board claim.
