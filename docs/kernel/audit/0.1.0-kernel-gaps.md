Statuses are assigned only from the commands above:

* **PROVEN** - a named test ran on this tree and its assertions cover the stated contract.
* **PARTIAL** - the positive or error side is proven, but not both, or the probe is narrower than
  the contract.
* **UNTESTED** - implementation exists and was read, but no test on this tree proves it.
* **MISSING** - no implementation was found.
* **SUSPECT** - code reading shows a concrete defect at `file:function:line`; the row names the
  settling test. A suspect is not a finding until that test fails.

## 7. Findings exposed by the refresh

1. **`fsd-ufs-rw` create after mount** - the probe mounts the image (`mode=rw journal=active`,
   `probe mount ok`) then fails `fsd-ufs-rw: probe: create: no such file or directory` and
   crash-loops. This is a new failure on `80cf30b3` (K451 passed); the row is PARTIAL. Proposed:
   "fsd-ufs-rw: create after rw mount returns ENOENT".
2. **blockd `block:0`** - `virtio-blk` fails `k15: probe: open block:0: no such file or directory`
   and `svcd: k15-probe failed: exited before it became ready`; the block device is not published.
   The driver row and a new blockd row are PARTIAL. Proposed: "blockd: publish block:0 before the
   k15/fsd-ufs probes run".
3. **`evq` under load** - the bounded probe passed in K463 on this commit, but the refresh run
   timed out at 280 s with `client bad hup count=0`. This is a host-load flake, not a new contract
   failure; the row stays PARTIAL and the hammer list asks for stabilization.
4. **`console-input` skip** - the case is now `skipped: needs the B65 serial-input harness`. The
   UART row is demoted to PARTIAL and proposes B65.
5. **`kernel-early-boot` 30 s cap** - the refresh run stopped at `cmdline:` with no failure line;
   the case's own 30 s cap is below the loaded host's boot time. No boot regression is claimed.
6. **`posix-fs` AP start** - `smp: cpu 2 did not start`, `2 cpus online`; the fixture lines did not
   run. This is an environment boot failure, not a VFS result; the prior PROVEN rows stand.
7. **`posix-fs-smp` 300 s deadline** - the refresh run reached iteration 28-40 with progress and no
   stall; this is the known TCG deadline, not the K391 lost wake. The K391 20/20 evidence stands.
8. **ABI table is current** - `abi-diff` passes on this tree; the stale `PROC_CHROOT`/`PROC_REBOOT`
   row is PROVEN.
