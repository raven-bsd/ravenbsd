# raven-libc-abi

The ravenlibc external ABI in Rust: `core`-only scalar aliases, Linux-valued constants and
`#[repr(C)]` records/opaque blobs. Every item is generated by `raven-libc-hdrgen` from
`libc/ravenlibc/abi/*.toml`, the single source of truth for doc 14 part A. The crate is
class P (`#![forbid(unsafe_code)]`), layer L0, has **no runtime dependency** and does not
call a kernel or server primitive.

| Module | Content |
|---|---|
| `types` | `size_t`, `time_t`, `off_t`, `wchar_t` (per arch), `CHAR_IS_SIGNED` |
| `structs` | `Stat`, `Dirent`, `Sigaction`, `SiginfoT`, socket records, pthread opaque blobs, `ZERO` on every type |
| `layout` | `StructLayout`/`FieldLayout`, `STRUCTS`, `find(name)` |
| `errno` | the `Errno` newtype over the generated table (`is_linux`, `is_bsd_extra`, `name`) |
| the 14 groups | the C constants, each with `ALL: &[(&str, i128)]` for the parity tests |

The `src/generated/` tree is committed: a review sees the value change in the TOML and in the
Rust and C outputs. Do not edit it by hand; run
`cargo run -q -p raven-libc-hdrgen -- generate`.

## Verification

```sh
cargo test -p raven-libc-abi
cargo build -p raven-libc-abi --target x86_64-unknown-none
cargo build -p raven-libc-abi --target aarch64-unknown-none-softfloat
cargo build -p raven-libc-abi --target riscv64gc-unknown-none-elf
```

`layout.rs`'s const assertions (`size_of`, `align_of`, `offset_of!`) make a wrong table fail
the build on every target. `tests/linux_abi_parity.rs` parses `raven-linux-abi`, compares every
overlapping name with the generated `ALL` tables (except the reasoned `deviations.toml` rows),
checks the doc 14 4.6 values, and (on the x86_64 host, with clang) compares every record's
size, align and offsets with a direct clang measurement. `tests/errno_contract.rs` proves the
`raven-abi` subset is equal-valued and complete.
