# Frozen RAVEN_1.0 ABI candidate

- `RAVEN_1.0.symbols` is generated by `cargo xtask libc-abi gen --root .` from
  `crates/raven-libc/Symbol.map`, the donor census and `abi/data-symbols.toml`.
- `RAVEN_1.0.txt` is a `raven-libc-mkmap freeze` recording of the linked
  `build/<arch>/libc.so.1`; the procedure is in `docs/libc-lint.md`.
- Both public name sets must match (`xtask/src/libc_abi.rs:802`).

## 2026-11-22 refresh (K457)

K436 (`9d1a30cb`) added the public `ptsname` export (`compat/ptsname.rs`,
`Symbol.map:541`, `Symbols.list:1159`) but did not regenerate this directory. The frozen
`.symbols` and `.txt` still held only `ptsname_r`, so
`xtask libc_lint::tests::real_tree_lint_is_clean` failed with
`ptsname is frozen but absent` and `mkmap .txt and .symbols name sets differ`.

The linked x86_64 DSO exports `ptsname@@RAVEN_1.0`, so the export side was correct and only
this stale frozen candidate was refreshed: `libc-abi gen` (records 1727 -> 1728) and a
`mkmap freeze` of the re-linked DSO, which also updates the function sizes that changed
since the 2026-11-20 recording. No symbol was deleted from the frozen node and the lint was
not disabled.
